# ADR-0005: Shared-secret login with stateless signed sessions

Date: 2026-11-11 · Status: accepted

## Context

Tailscale already limits who can reach the Mac mini (ADR-0003), but any device on the tailnet, or a
compromised one, could open the stream. The owner wants one login on the phone that lasts weeks,
and a path to real user accounts if this becomes a SaaS.

## Decision

- **Port.** `ports.Authenticator` has `Login(secret) → Session` and `Verify(token) → Principal`.
  The HTTP layer owns cookies and rate limiting; the adapter owns what a credential and a token are.
- **Adapter `auth/sharedsecret`.** One secret, generated by `watchmydog gen-secret` (20 characters
  from a 31-symbol alphabet without look-alikes, about 99 bits), stored in a git-ignored file with
  mode 0600. `WATCHMYDOG_SECRET` overrides the file. The secret is compared as an HMAC digest in
  constant time.
- **Sessions are stateless tokens**: `v1.<claims>.<HMAC-SHA256>`, with the key derived from the
  secret. Nothing is stored server-side, restarts keep everyone logged in, and **rotating the secret
  logs out every device**. TTL defaults to 30 days.
- **Cookie** `wmd_session`: HttpOnly (scripts cannot read it), Secure (HTTPS or localhost only),
  SameSite=Lax (not sent on cross-site POSTs, which blocks CSRF on login/pause/resume).
- **What is protected**: every `/api/*` route except `health`, `session`, `login`, `logout`, and all
  of `/media/*`, including the WebRTC signaling. The static web client is public so it can show
  the login screen; it contains no secrets.
- **Rate limiting**: 5 failed logins per client per 15 minutes, then HTTP 429 with `Retry-After`.
  The client is the peer address, or the first `X-Forwarded-For` entry only when the peer is
  loopback (the local `tailscale serve` proxy), so a remote caller cannot pick its own key.
- **Transport**: the service listens on `127.0.0.1:8080` only. `tailscale serve` terminates HTTPS
  with a valid certificate for `<host>.<tailnet>.ts.net` and proxies to it. The media proxy drops
  the session cookie before forwarding to go2rtc.
- `auth.disabled: true` exists for local development and logs a warning at startup.

## Consequences

- One shared credential, no per-device revocation. Rotation (delete `data/secret`, `make secret`,
  restart) is the "log out everywhere" button. Acceptable for a single owner.
- WebRTC media itself (UDP/TCP 8555) is not behind the login, but a session cannot start without
  authenticated signaling, and the port is only reachable on the LAN and tailnet.
- SaaS path: an OIDC adapter issues sessions from an identity-provider callback and `Principal`
  gains user and tenant IDs. Handlers already depend only on the port.
